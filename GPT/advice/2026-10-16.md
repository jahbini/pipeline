## Safari `.local` peer-link fallback

Three `<a target="_blank">` links to `http://mac-mini.local:4311/…` in
`puppeteer/ui/panels/panels.js` were missing the Cmd-click fallback
(line 61 peer_active pipe link, line 152 "▶ RUNNING on mini" banner,
line 1382 peer_sessions logdir column). Safari silently blocks popups
to HTTP on `.local` hostnames; see `puppeteer/GPT/ui/safari_local_http.md`
for the fix pattern. Patched on laptop + synced to mini.

**Rule**: any `<a target="_blank" href="http://*.local…">` needs the
inline `onclick="if(event.metaKey||…)return true; window.location.href=this.href; return false;"`
fallback. There are no exceptions.

## The real pipe-flipping bug (NOT a server issue)

User reported: opening `http://mac-mini.local:4311/pipe/hf__qwen__qwen3-8b`
in the writer UI would seemingly "shift" to
`hf__nvidia__qwen3-6-27b-nvfp4` whenever a step was restarted, and the
writer process on the mini kept getting a new pid every few seconds.

Root cause was **not** in the writer or shared ui_server. A
**laptop-side `pipeline_runner.coffee`** (child of
`/Users/jahbini/pipeline/ui_server.coffee`, laptop pid 48484) had been
running since 7:25 AM and was firing a `switch_pipe → control → launch`
burst at mac-mini:4311 every ~7 seconds:

```
POST /api/switch_pipe  body={"pipe":"hf__nvidia__qwen3-6-27b-nvfp4"}
POST /api/control      body={"pipeline":"train_lora","ui_values":{}}
POST /api/launch       body={"pipeline":"train_lora","ui_values":{}}
```

The forgotten driver was the sole source of writer's apparent "constant
respawn" — writer at rest, after the driver was killed, now receives
one `/api/status` per 60s from the user's open browser tab.

### Diagnostic recipe when the writer "won't stay on a pipe"

1. On the mini: `netstat -an -p tcp | grep ":4311"` — note TIME_WAIT
   peers.
2. If any non-browser client has many connections, write a small
   logging proxy to introspect:
   - Bind writer to `UI_PORT=4312`.
   - Run a Node TCP tap on 4311 that forwards to 4312 and parses HTTP
     request lines (including bodies). The one used today lives at
     `/tmp/tap4311.js`; recreate as needed.
3. Correlate client IP with `ps -ef | grep coffee` on each candidate
   host. The culprit is almost always a long-running local pipeline
   runner someone forgot to stop.

### Hygiene lesson

A pipeline_runner that force-sets `pipe` + `pipeline` on every tick
can masquerade as a server/UI bug when its driver is somewhere the
operator isn't looking. If you ever see a pattern of
`switch_pipe → control → launch` repeating in writer logs, blame the
driver first.
